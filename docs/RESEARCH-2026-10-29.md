# Research notes, 29 October 2026

What was checked before expanding the [plan](PLAN.md), with sources. Claims marked *secondary* come
from blogs or aggregators and were not confirmed against a primary source.

## Comparable projects

- **Stoat (formerly Revolt).** Rust backend, AGPL-3.0, single-server, no federation. Self-hosting needs
  MongoDB, MinIO, RabbitMQ and Redis plus LiveKit for voice, so it is a multi-service deployment rather
  than one binary. Sources disagree on when LiveKit voice landed; the more recent guides say it works.
  [Dedimax guide](https://www.dedimax.com/en/blog/self-host-your-own-discord-the-complete-guide-to-stoat-ex-revolt),
  [Wikipedia](https://en.wikipedia.org/wiki/Stoat_(software)),
  [PrivacyTools review](https://privacytools.io/app/stoat).
- **Spacebar (formerly Fosscord).** TypeScript reimplementation of Discord's own API, AGPL-3.0, still
  described as alpha in 2026. It cannot talk to discord.com. [Spacebar docs](https://docs.spacebar.chat/),
  [server repository](https://github.com/SpacebarChat/Server).
- **Mumble.** Client-server, TLS control channel plus UDP audio, Opus only since 1.5. This is the
  closest existing design to itson's voice path and has worked for gamers for years.
  [Mumble 1.5.634 release](https://www.mumble.info/blog/mumble-1.5.634),
  [Wikipedia](https://en.wikipedia.org/wiki/Mumble_(software)).
- **Discord's own protocol.** Gateway events carry sequence numbers; clients resume by reconnecting and
  replaying from the last sequence; compression is negotiated (`zlib-stream` or `zstd-stream`); the voice
  gateway acknowledges sequences and buffers for resume.
  [Gateway docs](https://docs.discord.com/developers/events/gateway),
  [Voice connections](https://docs.discord.com/developers/topics/voice-connections).
- **Discord DAVE.** End-to-end encrypted voice and video using an MLS group per call, a per-sender key
  ratchet exported from the group, AES-128-GCM frames with codec headers left in the clear for the
  packetizer, 30-digit call codes and 45-digit pairwise fingerprints for verification. The server
  forwards frames it cannot read. Audited by Trail of Bits. The whitepaper is CC BY-NC-SA 4.0; the
  `libdave` reference library (C++ and JavaScript) is MIT.
  [daveprotocol.com](https://daveprotocol.com/), [Discord blog](https://discord.com/blog/meet-dave-e2ee-for-audio-video),
  [libdave](https://github.com/discord/libdave).

## Home hosting

- **Cloudflare Tunnel public hostnames carry HTTP, HTTPS and WebSockets, not raw UDP.** Spectrum's UDP
  proxying is an Enterprise feature (*secondary*). A home host behind such a tunnel can serve itson text
  but not QUIC voice. [Cloudflare Tunnel FAQ](https://developers.cloudflare.com/cloudflare-one/faq/tunnel/),
  [Spectrum limitations](https://developers.cloudflare.com/spectrum/reference/limitations/),
  [alternatives write-up](https://thebiggish.pages.dev/news/ten-cloudflare-tunnel-alternatives-for-2026-udp-support-self-hosting-and-cost).
- **CGNAT blocks inbound UDP entirely.** Mobile connections cannot opt out; some ISPs sell a public
  address for a monthly fee; otherwise a relay on a cheap VPS (frp-style) or a mesh VPN is the way in.
  [CGNAT explained](https://ipfyi.com/guides/ip-basics/carrier-grade-nat-explained/),
  [frp for UDP](https://space-node.net/blog/frp-bypass-cgnat-minecraft-server-guide-2026).

## Voice

- **libopus 1.6.1 is what the `opus` 0.4.0 crate bundles** (via `opusic-sys` 0.7.6, checked in the local
  registry). `opusic-sys` has a `dred` feature that builds Deep Redundancy, but `opus` 0.4.0 exposes no
  features, so using DRED needs the `-sys` crate directly or a patched wrapper.
- **DRED** guards against burst loss up to about a second at roughly 1/50 of the Opus bitrate on top; in-band
  FEC covers single lost frames. [DRED paper](https://arxiv.org/html/2212.04453v3),
  [IETF draft](https://ftp.belnet.be/pub/ietf-ftp/internet-drafts/draft-valin-opus-dred-05.html),
  [bloggeek summary](https://bloggeek.me/webrtcglossary/dred/) (*secondary*).
- **Echo cancellation in Rust now has three routes:** `webrtc-audio-processing` (safe wrapper over the C++
  module, AEC3 by default), `sonora` (pure-Rust port of WebRTC M145 audio processing, with `sonora-aec3`),
  and `aec3` (a separate pure-Rust AEC3 port, 0.4.0). None was evaluated here.
  [webrtc-audio-processing](https://docs.rs/crate/webrtc-audio-processing/latest/source/README.md),
  [sonora](https://github.com/dignifiedquire/sonora), [aec3](https://crates.io/crates/aec3).
- **WebRTC in Rust:** `str0m` is a sans-I/O implementation used by Lookback as a server SFU; the
  `webrtc-rs` SFU is at 0.20 release candidates and its authors say it is not production-ready yet.
  [str0m](https://docs.rs/str0m), [webrtc-rs SFU announcement](https://webrtc.rs/blog/2026/07/13/announcing-sfu-v0.20.0-rc.3.html).
- **WebTransport** gives browsers QUIC datagrams without WebRTC. Rust crates: `wtransport` (over quinn),
  `web-transport-quinn` 0.10, `webtrans` 0.5 (July 2026, with WASM bindings). Media over QUIC (MoQ) is
  still an IETF draft with a December 2026 target to reach the IESG; analysts place production use in 2027.
  [wtransport](https://docs.rs/wtransport/), [web-transport-quinn](https://docs.rs/crate/web-transport-quinn),
  [webtrans](https://docs.rs/crate/webtrans/latest), [IETF MoQ group](https://datatracker.ietf.org/group/moq/about/),
  [MoQ status 2026](https://www.forasoft.com/blog/article/media-over-quic-moq-streaming-2026) (*secondary*).

## Desktop toolkits and accessibility

- **iced 0.14:** no AccessKit in upstream. Issue #552 is open with `help wanted`, the last comments are
  from December 2025, and no pull request is linked. System76's fork and the `plushie-iced` fork add
  AccessKit. [iced issue #552](https://github.com/iced-rs/iced/issues/552),
  [plushie-iced](https://lib.rs/crates/plushie-iced), [2026 Rust GUI survey](https://blog.wybxc.cc/blog/rust-gui-survey-2026/).
- **egui/eframe 0.37:** AccessKit on by default (confirmed from the crate's feature list in the local registry).
  [egui AccessKit PR](https://github.com/emilk/egui/pull/2294).
- **Xilem/Masonry:** AccessKit built in; latest release v0.4.0, still called alpha. Masonry is the widget
  layer. [releases](https://github.com/linebender/xilem/releases), [docs](https://docs.rs/xilem/latest/xilem/).
- **Slint:** AccessKit since 1.1 on all desktop platforms; licences are royalty-free, GPLv3 or paid. It uses
  its own `.slint` markup language. [Slint 1.1 notes](https://www.oschina.net/comment/news/246945) (*secondary*),
  [licence listing](https://github.com/sdroege/slint).

## Security

- **Argon2id, OWASP Password Storage Cheat Sheet:** minimum 19 MiB memory, 2 iterations, parallelism 1, or
  the equal-strength alternatives m=46 MiB/t=1, m=12 MiB/t=3, m=9 MiB/t=4, m=7 MiB/t=5.
  [OWASP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- **OpenMLS** implements RFC 9420 in Rust, maintained by Phoenix R&D and Cryspen; 0.9 is at release
  candidates. No audit or production-adopter list was found. [OpenMLS](https://github.com/openmls/openmls).

## Release engineering

- **Windows signing:** Azure Artifact Signing (formerly Trusted Signing) costs about USD 10 a month for
  5,000 signatures; individuals are eligible only in the USA and Canada, organisations also in the EU and
  UK; it does not grant instant SmartScreen trust, reputation builds across releases. SignPath (free for
  open source) and Certum's open-source certificate (about EUR 25 a year) were mentioned but not verified.
  [Microsoft code signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options),
  [pricing comparison](https://my-ssl.com/learn/azure-trusted-signing-vs-code-signing-certificate) (*secondary*).
- **Cross-compiling for Windows:** `x86_64-pc-windows-gnu` with mingw-w64 is the simplest Linux-hosted
  route; `cargo-xwin` targets MSVC and wants LLVM plus a cached Windows SDK. Native Windows CI runners
  avoid both. [cargo-xwin](https://docs.rs/crate/cargo-xwin/0.23.0),
  [forum thread](https://users.rust-lang.org/t/building-for-x86-64-pc-windows-msvc-in-gitlab-ci/136223).
- **Packaging:** `cargo-packager` makes MSI (WiX) and NSIS installers, `.deb`, `.rpm` and AppImage;
  `cargo-dist` orchestrates releases; Flatpak needs a manifest with vendored sources because Flathub
  builds without network. [cargo-packager](https://docs.rs/crate/cargo-packager/latest/),
  [cargo-dist](https://docs.rs/crate/cargo-dist/latest/source/src/tasks.rs),
  [Flatpak and Rust](https://develop.kde.org/docs/getting-started/rust/rust-flatpak/).
- **Push notifications for a later mobile app:** UnifiedPush with a self-hosted ntfy server works on
  Android; iOS requires Apple's APNs. [UnifiedPush distributors](https://unifiedpush.org/users/distributors/),
  [ntfy](https://etke.cc/help/extras/ntfy/).
